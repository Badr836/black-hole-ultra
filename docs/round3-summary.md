# الجولة الثالثة — ملخص تنفيذي

> التاريخ: 2026-10-30 · الحالة: **الخطوات الثلاث مُنفَّذة ومُختبرة فعلياً**
> البوابات: typecheck ✅ · lint ✅ · **116/116 اختبار** ✅ · build ✅ · e2e 19/19 ✅ · UI 0 أخطاء

نُفِّذت الخطوات الثلاث التي كانت «مقترحة ولم تُنفَّذ» في نهاية الجولة الثانية.

## 1) قائمة تشغيل حقيقية ≥10 عناصر — تحقّق رقمي لا نظري

| الاختبار | النتيجة |
|---|---|
| قائمة يوتيوب حقيقية، العناصر 1-10 | **10 ملفات محفوظة**، `completedEntries=10`، `missingItems=[]`، **لا تنبيه** |
| القائمة نفسها مع فهرس غير موجود (`1-4,999`) | «**حُفظ 4 من 5**، الناقص #999» — والحالة `completed` **لا `failed`** |
| شريط التقدّم | يتحرك بالعنصر (0→33→66%) لا بالملف الواحد (كان يثبت عند 99.9%) |

كيف يُحسب؟ ثلاث مصادر تُطابَق: ما طلبه المستخدم (`--playlist-items`)، علامات `before_dl:BHITEM` لكل
عنصر، وملفات `after_move:BHFILE` التي نزلت فعلاً. الفرق = الناقص، مع سطر `ERROR` المقابل كسبب.

## 2) مزوّد HLS ثالث: N_m3u8DL-RE — قرار الترخيص أولاً

| السؤال | الجواب |
|---|---|
| الترخيص | **MIT** (مؤكَّد عبر GitHub API، 9,005 نجمة) |
| هل ننسخ كوده؟ | **لا** — ثنائي خارجي فقط، لا سطر مصدري في المستودع |
| النطاق | روابط `.m3u8` فقط، ويُستدعى تلقائياً عند فشل yt-dlp على HLS |
| DRM | **مرفوض برمجياً**: فحص المانيفست قبل التنزيل (`SAMPLE-AES`/Widevine/PlayReady/FairPlay)، ولا `--key` أبداً |

**النتائج الفعلية:** بث اختباري 47.6MB نُزّل عبر `provider=nm3u8dl` مع تقدّم
17.1→31.7→43.9→61.0→75.6→95.1% واحترام حد السرعة (1.5MB/s). ورابط 404 يفشل الآن في **2 ثانية**
برسالة عربية بدل ~50 ثانية.

## 3) إعادة تحميل العناصر الناقصة (Retry-incomplete)

- زر **«إعادة الناقص (N)»** يظهر في الطابور للعناصر المكتملة الناقصة.
- يطلب **الفهارس الناقصة فقط** (`--playlist-items 2,5-6`) — لا إعادة تحميل لما اكتمل.
- **حد أقصى محاولتان**، ثم رفض صريح: «غالباً العنصر محذوف أو خاص — لا فائدة من تكرار المحاولة».
- الملفات السابقة **لا تُمحى** من السجل؛ الملفات الجديدة تُدمج معها.
- التجربة الحقيقية: عنصر مفقود واحد ⇒ نُزّل **ملف واحد فقط** ثم أُفرغت قائمة الناقص.

## 4) سبعة أعطال حقيقية اكتُشفت أثناء التنفيذ وأُصلحت

1. `playlist:` في yt-dlp يُطبع مرة واحدة للقائمة (فهرس `NA`) ⇒ استُبدل بـ`before_dl:`.
2. **`metadata` لم تكن تُكتب إطلاقاً** في مسار الإكمال (بثّ الحقول أعلى الكائن بدل داخله) — لولا ذلك لضاع `missingItems` بصمت.
3. `--print` يُسكت yt-dlp ⇒ أُضيف `--no-quiet` وعلامات `BHDEST/BHITEM/BHFILE`.
4. N_m3u8DL-RE ينهار عندما يكون خرجه أنبوباً (خلل Spectre.Console) ⇒ `--force-ansi-console`.
5. تقدّم HLS كان يقفز إلى 99.9% بعد المسار الأول ⇒ حساب تراكمي بعدد المسارات.
6. محاولة ناقصة لا تنتج شيئاً كانت تقول «الملف موجود مسبقاً» (مضلّل) ⇒ رسالة صحيحة تحفظ الناقص.
7. فشل 404 كان يستهلك ~50 ثانية من المحاولات ⇒ كشف فوري وإيقاف.

## 5) ما لم يُنفَّذ ولماذا

- **لا دعم DRM** بأي شكل (سياسة المشروع، وأربعة بلاغات مستخدمين تطلبه رُفضت).
- **لا نسخ كود** من Seal/YTDLnis/Gopeed/cobalt (GPL/AGPL) — الأفكار أُعيد تنفيذها.
- **إعادة تحميل تلقائية بلا زر**: بقيت يدوية عمداً؛ التكرار التلقائي لعنصر محذوف لا يفيد.
- **قوائم HLS متعددة الجودة عبر N_m3u8DL-RE**: يختار الأداة أفضل مسار تلقائياً (`--auto-select`)؛ اختيار
  جودة بعينها لكل مسار يحتاج واجهة جديدة — مؤجّل.
