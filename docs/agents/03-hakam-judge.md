# الوكيل الثالث — «حَكَم» (Judge)

قرأت الخطة، والاعتراضات، والكود بنفسي في المواضع المتنازع عليها. أحكامي أدناه **ملزمة**،
وليست اقتراحاً. ما رُفض لا يُنفَّذ في هذه الدورة، وما عُدِّل يُنفَّذ بصيغتي لا بصيغة أي طرف.

---

## أ. الأحكام

### 1) الهجرة إلى SQLite — **يُعتمد بصيغة الحكم**
حجة «باني» صحيحة: طلب PostgreSQL يهدم وعد «محلي أولاً» ويحرم مستخدم Windows من التطبيق قبل
أول شاشة. اعتراض «ناقد» على غياب المخطط المُصدَّر صحيح أيضاً.
**الصيغة المعتمدة:**
- `better-sqlite3` + `drizzle-orm/better-sqlite3`، ملف `data/blackhole.db`، WAL، `busy_timeout=5000`.
- **هجرات مرقّمة** في `src/db/migrations.ts` مع جدول `__meta(version)`، تُطبَّق بالترتيب داخل معاملة.
  لا `CREATE TABLE` مبعثر. هذا يمنع انحراف المخطط ويجعل الترقية لاحقاً ممكنة.
- `DATABASE_URL` يصبح مهجوراً ويُحذف من `package.json` و`.env.example` و`README`.
- معيار القبول: حذف `data/` → `npm run dev` → `/api/health` ok، وإدراج `metadata` JSON
  وقيمة > 2^31 بايت وقراءتهما سليمين.

### 2) السباق في كتابة الحالة — **يُعتمد، مع تشديد الناقد**
- طابور كتابة متسلسل لكل مهمة (سلسلة وعود).
- **استحواذ ذرّي** على المهمة: `UPDATE ... SET status='downloading' WHERE id=? AND status='queued'`
  ثم التحقق من الصفوف المتأثرة (بند ن11). هذا يمنع التحميل المزدوج ويُغني عن قفل خارجي.
- حارس رتابة: لا تراجع عن `completed`، ولا كتابة تقدّم بعد الاكتمال.
- فشل الكتابة يُسجَّل مرة واحدة لكل مهمة (لا `catch {}` أعمى).
- معيار القبول: اختبار بتأخير صناعي مُدخَل **يفشل على المنطق القديم** وينجح على الجديد.

### 3) انتحال المتصفح — **يُعتمد بالصيغة المشدَّدة**
- كاش وحدة لمدة 10 دقائق، يُقرأ الناتج النصي فقط لا رمز الخروج، ويُشترط ألا يحتوي السطر
  على `unavailable`.
- عند غياب الدعم: لا يُمرَّر `--impersonate`، وتُبقى الترويسات، وتُضاف ملاحظة في التشخيص.
- تُضاف `curl_cffi` إلى تعليمات التثبيت (`pip install -U "yt-dlp[default,curl-cffi]"`).

### 4) الرابط المباشر — **يُعتمد بشرط الناقد**
الخيار الاحتياطي يُبنى من `format_id` حقيقي فقط، ولا يُصطنع خيار إذا كانت `formats` فارغة.
معيار القبول: تحميل mp4 مباشر → `completed` + `ffprobe` يؤكد مسار فيديو.

### 5) الأمن — **يُعتمد مع رفض جزئي لـ«باني»**
- `--no-check-certificates` **لا يُحذف**، بل يصبح إعداد `allowInsecureTls=false` افتراضياً.
  (اعتراض الناقد مقبول: شبكات الشركات حالة مشروعة.)
- `outputDir` من جسم الطلب يجب أن يكون داخل جذور مسموحة؛ الجذر المسموح = `DOWNLOAD_DIR`،
  مجلد المنزل، أو المسار المحفوظ في الإعدادات (لأن المستخدم اختاره بنفسه بنيّة صريحة).
- قالب التسمية يُنظَّف: يُرفض `..` والفواصل وأي مسار مطلق.
- **الملف المخدوم** يُتحقق أنه داخل جذر مسموح بعد `realpath` (يمنع symlink للخارج).
- محلّل `Range` صارم: أرقام فقط، `start<=end`، وإلا 416 مع `Content-Range: bytes */size`.
- الاختبارات تغطي: `%00`، مطلق، `..`، symlink يونيكود مموّه.

### 6) وضع الشبكة — **يُعدَّل: مرفوض حل «باني»، مقبول بديل «ناقد»**
- الرمز الإلزامي **مرفوض** كخط دفاع أول (يكسر تجربة المتصفح ويُدسّ في العميل).
- المعتمد: فحص `Origin` على الطلبات المُغيِّرة عند وجوده ومقارنته بـ `Host`؛ غيابه مسموح
  (curl/E2E). رمز `BLACKHOLE_TOKEN` **اختياري** ومُعطَّل افتراضياً.
- **قيد إلزامي:** لا يكسر معاينة البيئة المستضافة (Proxy origin ≠ Host الداخلي)، لذا
  الفحص يقارن بمضيف الطلب الفعلي (`req.headers.host`) لا بعنوان ثابت.

### 7) الميزات — **قبول مُعاد ترتيبه**
- **يُرفض الآن:** اختيار عناصر قائمة التشغيل بواجهة كاملة — «ناقد» محق: البيانات أسفلها كاذبة.
  لكن **محاسبة الملفات المتعددة تُنفَّذ الآن** (مصفوفة `files`, عدّاد `completedEntries`).
  ويُضاف دعم `playlistItems` في الـAPI فقط (سلسلة على نمط `1-5,8`) دون واجهة معقّدة.
- **يُعتمد:** حذف الملف من القرص مع الخيار (`deleteFile=true`)، نسخ/استعادة الإعدادات،
  إحصاءات التخزين، فحص المساحة الحرة، حدّ تزامن للتحليل + كاش قصير.
- **مرفوض نهائياً في هذه الدورة:** aria2c، BitTorrent، ed2k، التحميلات المجدولة، عمل Flutter.
  السبب: تكلفة عالية + اعتماديات خارجية تناقض «محلي أولاً».

### 8) الاختبارات — **يُعتمد بمعايير الناقد**
- `node:test` + `tsx`/`node --experimental-strip-types` لمنطق نقي، بلا شبكة.
- أربعة اختبارات يجب أن تُظهر فشلاً على المنطق القديم: السباق، Range، فحص المسار، التقدّم بعد الاكتمال.
- E2E يتخطّى نفسه إذا غاب yt-dlp/الشبكة، بحد زمني 180 ثانية.
- بوابة القبول: `typecheck` + `lint` + `test` + `build` + `E2E` + `diagnostics.ok`.

### 9) «ن1» كود ffmpeg الميت — **حكم قاطع**
`start()` لا يجوز أن يفشل عند غياب ffmpeg لمهمة لا تحتاجه. المعتمد: ffmpeg مطلوب **فقط**
عند (دمج، تحويل، دمج صوت، تضمين، ترجمة، WMA). تحميل ملف واحد بصيغة واحدة يعمل بدونه.
هكذا يصبح مسار `buildArgs` حياً، ولا كود ميت ولا سلوك متناقض.

### 10) البنود ن2، ن3، ن5، ن6، ن7، ن8 — **تُعتمد كلها** (تحقق من enums، مؤقت الواجهة،
حجب `--add-headers`/`Authorization` من السجلات، حدّ تزامن التحليل، بيانات الحزمة، `.gitignore`).

## ج. بوابة الاعتماد النهائي (Judge Gate)

النسخة تُعتمد فقط إذا — في بيئة تشغيل حقيقية — تحقق **كل** ما يلي:

1. `npm run test` أخضر (وحدات + حالات الفشل التاريخية موثقة).
2. `npm run typecheck` و`npm run lint` و`npm run build` بلا أخطاء.
3. `npm start` يستمع ويعمل `/api/health` و`/api/system` و`/api/diagnostics` = ok.
4. تحميل حقيقي (فيديو) → `completed`، والحجم > 0، و`ffprobe` يؤكد الترميز.
5. تحميل صوتي (M4A) → `completed` و`ffprobe` يؤكد مسار صوت.
6. طلب `Range` بالبايت يعيد 206 وأحجاماً صحيحة، والطلب الشاذ يعيد 416.
7. إعادة تشغيل الخادم: لا صفوف عالقة في `downloading`، والملفات المفقودة تُعلَّم `missing`.
8. لا `Any` صريح ولا `@ts-ignore` جديد، ولا `catch {}` جديد يبتلع الأخطاء في المسارات الحسّاسة.

**أي بند يفشل في البوابة = لا اعتماد، حتى لو نجح كل ما عداه.**
