# بروتوكول الوكلاء الثلاثة — BlackHole Ultra

هذه الدورة ليست تمريناً شكلياً: كل ادعاء فيها مرتبط بسطر في الكود أو بنتيجة أمر مُنفَّذ،
والحكم يُلزم التنفيذ بما اتُّفق عليه فقط.

## الأدوار

| الدور | الملف | المهمة | قاعده |
|---|---|---|---|
| **باني** (Proponent) | `01-bani-proposer.md` | يقترح خطة البناء والتحسينات ويبرّرها | يجب أن يقدّم أدلة `ملف:سطر` + معيار نجاح قابل للقياس |
| **ناقد** (Challenger) | `02-naqid-challenger.md` | يهاجم كل بند: مخاطر، إفراط هندسي، نقص أدلة، آثار جانبية | لا يُقبل اعتراض بدون إثبات من الكود أو التجربة |
| **حكم** (Judge) | `03-hakam-judge.md` | يفصل: يُعتمد / يُعدَّل / يُرفض لكل بند + سبب + تكلفة | لا يختار الأسهل، يختار الأصح لهدف المشروع |

## القاعدة الحاكمة (Definition of Done)

لا يُعتمد أي بند إلا إذا استوفى الأربعة:

1. **دليل** — مشكلة موثقة (سطر/سجل/تجربة).
2. **إصلاح** — كود مكتوب فعلياً، لا وصف.
3. **إثبات** — اختبار أو أمر ينجح بعد الإصلاح ويفشل قبله إن أمكن.
4. **عدم انحدار** — `tsc --noEmit` + `next build` + اختبارات الوحدة تظل خضراء.

## سجل الجلسة

- الكود المدروس: `BlackHole-Ultra-Downloader-Source.zip` (4,939 سطراً، نسختا Web + Flutter).
- البيئة المستخدمة للفحص: Linux، Node 20.20.2، yt-dlp 2026.10.26، FFmpeg/FFprobe 7.1.5.
- نتيجة الفحص الأولي: يوتيوب يعمل من هذه البيئة؛ `--list-impersonate-targets` كشف أن
  `curl_cffi` غير مثبّت (الهدف الوحيد المتاح: Tor «unavailable») — وهذا يغيّر حكماً كاملاً في البند المتعلق بـ TikTok.
